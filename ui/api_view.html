Data Access & API

The FJORDLAB DATA PORTAL exposes a unified programmatic interface based on the OGC SensorThings API (v1.1) standard. This open, geospatial-enabled standard allows for the interconnection of IoT devices, data, and applications over the Web. Our implementation aggregates data from distributed nodes (federation) into a single logical entity model consisting of Things, Datastreams, Sensors, and Observations.

https://{host}/api/v1/
Bearer Token (JWT)
HTTP (REST) & MQTT
JSON, JSON-LD

Base URL & Authentication

All API endpoints are relative to the federation entry point. Replace {host} with your specific regional gateway or the central orchestrator.

https://federation.fjordlab.no/api/v1/

Requests must include the Authorization header using a valid API Key or OAuth2 Bearer token.

// Header Example Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... Accept: application/json

Quickstart Examples

1. List Things

GET /Things // 200 OK - Returns list of registered things (vessels, buoys, sites)

2. Filter Observations by Time

GET /Observations?$filter=phenomenonTime gt 2025-01-01T00:00:00Z // 200 OK - Returns observations after Jan 1st, 2025

3. Expand Relations

GET /Datastreams(1)?$expand=Observations // 200 OK - Returns Datastream 1 and its nested Observations

4. Select Specific Fields

GET /Things?$select=name,description,properties // 200 OK - Returns only requested fields to reduce payload size

5. Pagination

GET /Observations?$top=50&$skip=100 // 200 OK - Skips first 100, returns next 50 records

6. Create Observation

POST /Observations { "phenomenonTime": "2025-12-15T10:00:00Z", "result": 12.5, "Datastream": { "@iot.id": 1 } } // 201 Created

Create, Update, Delete

Standard HTTP methods are used for entity lifecycle management.

Create

Use POST to create new entities. The response will include a Location header to the new resource.

Update

Use PATCH to partially update an entity (preferred). Use PUT for full replacement.

PATCH /Things(1) { "description": "Updated description for R/V Gunnerus" } // 200 OK

Delete

DELETE /Observations(999) // 204 No Content

Batch Requests

Submit multiple requests in a single HTTP call to reduce latency. Send a JSON array of requests to the $batch endpoint.

POST /api/v1/$batch { "requests": [ { "method": "POST", "url": "Observations", "body": { ... } }, { "method": "GET", "url": "Things(1)" } ] }

Efficient Encodings (Data Array)

For large datasets, use the Data Array format to reduce JSON verbosity by separating keys from values.

// Response Format { "Datastream": { "@iot.id": 1 }, "components": ["phenomenonTime", "result"], "dataArray": [ ["2025-01-01T10:00:00Z", 12.4], ["2025-01-01T10:01:00Z", 12.6] ] }

MQTT (Streams / Realtime)

Creating Observations

Publish JSON payloads to the following topic structure to ingest data.

Topic: api/v1/Datastreams({id})/Observations Payload: { "result": 15.5, "phenomenonTime": "..." }

Receiving Updates

Subscribe to receive push updates when new data arrives.

Subscribe: api/v1/Datastreams(1)/Observations
